# Phase 4: one-command local automation

The user no longer needs to create `.lvproj` files by hand.

Use PyCharm's terminal in the repository root:

```powershell
git pull
python -m unittest tests.test_phase4_create_projects tests.test_phase4_oneclick -v
```

Then execute **one command**:

```powershell
python -m scripts.phase4_oneclick --manifest "configs/phase4_sum_batch_template.json" --template "D:\Phase4\NativeVerification\FtoCVerification.lvproj" --scratch-root "D:\Phase4\NativeVerification\Sum" --output-dir "D:\Phase4\review\sum-oneclick-v1"
```

The command will:

1. Verify original and scratch VI hashes from the manifest.
2. Create `SumVerification.lvproj` by cloning the already-working
   `FtoCVerification.lvproj` layout, adding the scratch Sum VI only.
3. Run the read-only LabVIEW MCP self-test on the scratch VI.
4. Run the generation batch preflight.
5. Save `oneclick-report.json` and the nested preflight report.

The first run intentionally reports `blocked_review` because the
manifest's `manually_reviewed` and
`risk_accepted_for_generation` flags are **false**. This is an
approved safety gate, not a program error. The command will not
automatically set these flags.

To generate test VIs later, obtain a reviewed/approved local manifest
with `manually_reviewed=true`, `risk_accepted_for_generation=true`,
`allow_vi_execution=false`, with independently verified expected values.
Then use a NEW output folder and add `--generate` to the same command.
The test VI will be generated but not executed.

**Native Caraya execution is not yet integrated.** The JUnit collector
works on XML reports generated by a separately reviewed Caraya runner.
Until the runner has been validated, claim only project creation,
preflight, and approved generation as automated.

No manual LabVIEW project creation, no original VI modification, no
cloud upload, no training approval.
